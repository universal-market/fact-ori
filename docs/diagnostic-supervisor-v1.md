# Offline diagnostic supervisor component v1

This first implementation component addresses Q8-F1's parent-deadline requirement. It does not implement the real-model harness. `scripts/diagnostic_supervisor.py` supervises one trusted caller's POSIX child command in a new session/process group, accepts fixed ordered phase-completion metadata, and enforces monotonic phase and total work deadlines with reserved cleanup time. Repeated, out-of-order, malformed or extra-field events fail closed. It requires the child to exit after the final phase. No production entry point calls this module.

The parent drains bounded stdout/stderr using selector events. Receipts retain accepted phase names, failure category and observed-prefix byte counts/hashes, without publishing raw child text, parser excerpts or exception strings. The output cap may be exceeded by at most one read chunk. These hashes describe bytes actually observed, not all bytes a terminated child might have emitted. This is a metadata-only partial receipt, not the future semantic-result sanitizer or preservation of full model answers.

Cleanup sends SIGKILL only to the process group created by this Popen and reaps its leader before returning. The Linux test also observes an authored descendant no longer running. Descendants that deliberately escape the group, general descendant reaping, OS scheduling guarantees, process-creation hangs, external Docker/network resource cleanup and real inference keepalive are outside this component's demonstrated coverage. Caller-supplied argv and phase names are trusted code configuration; child signals cannot establish semantic correctness. A child can claim completion without doing model work, so a separately reviewed result checker remains necessary.

Run `python -B -m unittest discover -s scripts -p 'test_diagnostic_supervisor.py' -v`. Thirteen actual local child fault tests cover success, startup/case hangs and partial phases, a repeated phase, outer deadline priority, hung exit, nonzero/incomplete exit, raw-text omission, output flood, extra payload rejection, a same-group descendant and invalid limits. Tests use scaled subsecond caps, not a 600-second workload or resource-sufficiency measurement. No model, Docker daemon, network, cached model filesystem or backend is accessed by these tests.
