# Self-hosted semantic evidence API

This deployment uses the [official self-hosted Convex backend](https://github.com/convex/convex-backend/tree/main/self-hosted)
with SQLite in the dedicated `fact-ori-pilot_factori-data` Docker volume.
It needs Docker Compose, Node >=22 and Python >=3.10. No Convex account,
Cloudflare account, domain purchase or paid service is required.

## Prepare privately

After source review, from a trusted maintainer checkout:

```sh
npm ci
npm run typecheck
npm run test:convex
npm run test:python
npm run test:gateway
bash scripts/self-hosted.sh prepare
```

The script exports the validated library seed, starts the private evidence
backend and Ollama, downloads the pinned embedding/chat models, builds the
semantic and operator images, enables opted-in research, deploys the backend
and imports the approved seed. It starts the semantic API and recreates the gateway so replaced bind-mounted
configuration files cannot retain an old inode. Readiness requires semantic
capabilities and the current checkout engine fingerprint, then it probes all
published evidence/mappings. A plain nginx reload cannot refresh an old file mount.

Deployment authority is generated by this isolated instance and piped straight
into an ephemeral deployment container. It never uses a personal account,
host login, other-project database or credential file. The owner explicitly
authorized this instance-local pipeline. Never trace it or log its stdin/environment.
Preparing containers alone does not deploy or seed the application.

The image build context is allowlisted by `.dockerignore`: package manifests,
Convex source, semantic source, public snapshot, operator scripts and approved seed. It
excludes `.env*`, `.git`, private state and other data. Images are pinned by
digest. Changing a digest requires review and verification.

The backend and semantic/inference services have **no published host ports**.
The backend and semantic API use only the private network and their separate
volumes. Inference can download models but has no public listening route. The operator container receives no Docker socket or host home.
The gateway binds `127.0.0.1:43211` and allows only GET `/health`, POST
`/v1/check`, GET `/v1/checks/<analysis-id>`, GET `/v1/jobs/<job-id>`,
GET `/v1/records/<claim-id>` and relevant OPTIONS. Admin,
dashboard, generic Convex queries and other routes return 404 at the gateway.
Raw request paths must also match the allowlist: encoded slashes/dots, dot
segments and repeated-slash aliases cannot enter an allowed location while
forwarding a different raw route. Health and check accept no query string;
record query strings allow ASCII letters/digits, `=`, and `&` (including either
version/hash order). Parameter validity remains the application's responsibility.
A 16 KiB request limit and a small gateway rate limit bound pilot traffic;
rate limiting uses the connection source, so tunnel traffic shares a bucket.
This is a pilot resource bound, not per-user quotas or a DDoS guarantee.

`npm run test:gateway` starts the actual pinned nginx image/config against an
isolated echo upstream, uses raw HTTP request targets (without client URL
normalization), and checks allowed routes, encoded/literal traversal rejection,
methods and body size. It uses no database, credential or tunnel, then removes
only its uniquely named disposable test containers/network. It does not prove
Convex routing or application behavior; run the real API probe after deployment.

## Expose the verified API

```sh
bash scripts/self-hosted.sh publish
# Read only the generated public trycloudflare.com URL from tunnel logs.
docker compose --env-file /dev/null -f deploy/self-hosted/compose.yaml logs tunnel
node scripts/probe-public-api.mjs https://<generated-name>.trycloudflare.com --intake-enabled
```

[Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)
are temporary development endpoints with no uptime guarantee. Anyone can call
this API; the machine must stay online. The random URL can change after a
restart. The tunnel reaches only the allowlisted gateway and cannot reach the
private backend network. No router ports or existing Tailscale settings change.
Convex's internal origin settings stay private; this API currently returns no
file-storage URLs or callbacks that require a public Convex backend origin.
Review those settings before adding such capabilities.

Do not publish a URL until the exact source has technical review and both local
and external probes pass. `implementation_review: pending` remains explicit;
container/image/deployment records alone do not establish runtime attestation
or factual correctness. Existing review receipts bind only their stated inputs.

## Operate and preserve data

```sh
bash scripts/self-hosted.sh status
bash scripts/self-hosted.sh stop
```

Containers restart unless stopped. Stopping preserves all three dedicated volumes (evidence, analysis state and models). Never use
`down -v`, prune volumes or replace the volume to "fix" a deployment. Inspect
an existing instance before any re-import: the import intentionally changes the
active approved library but retains frozen versions. Opted-in research jobs and analysis requests are public writes.

Before upgrades or accepting irreplaceable data, stop the backend and make an
offline backup of its dedicated volume from trusted operator context, then
restart and probe. Restore into a separate volume/instance and verify before
switching; do not overwrite a live database. No automatic backup or tested
restore is claimed yet. Approved seed data can currently be reconstructed from
the repository. Operator receipts and public URLs belong in ignored local
state; never include keys or private host identifiers in a public receipt.

Contributors receive PR access only. Secret-free CI tests their proposed code;
reviewed source is deployed by the maintainer. Access to the host or Docker
daemon can bypass container isolation and is outside the public API boundary.

## Research handoff

```sh
bash scripts/self-hosted.sh outbox
bash scripts/self-hosted.sh operator checks:listForReconciliation \
  '{"status":"in_progress","paginationOpts":{"numItems":20,"cursor":null}}'
```

Use the allowlisted claim/link/reconcile functions described in [the backend
contract](api.md). Claims expire after five minutes. Search Tilori for duplicate
work before creating a post and use the job’s stable posting idempotency key.
This is the application’s research outbox, not Tilori’s notification event queue.
The librarian reads and processes it in ordinary work sessions. No new agent
listener, subscription consumer, or recurring schedule is introduced.

Run `npm run test:semantic` and the [real-model acceptance runner](semantic-api.md)
as well as the Python, Convex, type and gateway checks before promotion.
