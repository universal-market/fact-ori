# Offline partial-result and failure-report integration: proposed design v2

This separately versioned Q13 correction addresses Q12-F1/F2; v1 and its REVISE review remain immutable. This is a design for the next finite offline component, not an implemented harness or sanitizer. It addresses a concrete gap: the accepted worker-v2 keeps case results only in memory until both cases return, whereas the accepted supervisor preserves timing metadata only. A failure during case two can therefore lose a valid case-one result. Both accepted components and all Q8/Q9/Q10/Q11 inputs and receipts remain frozen. The successor must use new files and receive exact implementation review after this design review.

## Proposed worker checkpoint protocol

A new variant, not an edit of worker-v2, exposes the existing sequential case loop. It checks the same pinned protocol before snapshot path use, snapshot/import/model pins/fingerprint and no-consent fixture. Parent creates a fresh private local directory (0700) and random run identifier; identifier is a correlation value, not an authentication credential. It passes a fixed absolute directory and identifier via trusted argv. No paths are read from fetched content or checkpoint contents.

After each complete engine result, the child invokes the accepted v2 finite validator. On success it writes a UTF-8 JSON envelope with the exact keys in design.json to an exclusively created temporary file (0600), flushes it, then atomically renames it to one of exactly two fixed basenames: 01-capital.json, 02-unknown.json. No overwrite or retry: pre-existing destination fails the run. A private newly created directory and one trusted writer are prerequisites; ordinary rename is not advertised as race-proof no-clobber against another writer. Crash before rename leaves an ignored temporary file; crash after rename leaves a reconcilable complete result. Write/flush/close/rename errors become fixed failure categories, never raw exception text. Disk persistence across power loss is outside scope (no durability claim from flush alone).

Only after successful rename may the child emit the existing exact phase_complete event. Startup still emits only after initialization. Stdout accepts the supervisor's unchanged three ordered events; no payload extension, raw result, heartbeat or reset. A missing event is a supervision failure even if its checkpoint is valid. A phase event alone never makes a checkpoint valid. The child never writes a case after its validation failed. Later cases are not attempted after a failure. A future implementation may reuse helpers, but changed code requires a new exact review; no automatic approval inheritance.

## Parent reconciliation and races

Parent calls the accepted supervisor, then reconciles files only after it returns and its child leader has been reaped. If leader_reaped is not true, do not read the potentially changing directory: mark cases not_reconciled, run failed/not_reconciled and fixed cleanup limitation. The accepted process-group supervisor cannot establish absence of escaped descendants; trusted non-escaping fixture worker is a scope precondition. Symlink-safe paths and bounded I/O are defense in depth, not a hostile filesystem sandbox.

Open only the two fixed paths with no-follow semantics; require ordinary files with single link, regular expected ownership, no symlink, and per-case size at most262144 bytes. Read at most cap+1, reject non-UTF8, duplicate JSON keys, malformed JSON, wrong envelope keys/types or mismatched run identifier/case ordinal/input digest/implementation/worker digest/import. Recheck stable size/metadata through the same open descriptor; never glob names or follow a checkpoint-supplied path. Ignore temporary/extra files for results, but remove only the fresh owned directory at teardown. These details need explicit implementation probes, including swap/size races; no acceptance of those probes is implied here.

Use a separately supervised offline Node reconciliation child that imports the immutable v2 validator, rechecks all pinned inputs, parses bounded JSON using a duplicate-key-rejecting mechanism, and validates each result again. The parent must not deserialize/re-emit arbitrary raw result strings. A compliant parser is an implementation requirement, not a capability of ordinary JSON.parse. Reconciliation child receives fixed filenames/expected values from trusted config. Its stdout is metadata only under the accepted supervisor; the allowlisted reconciliation result is written to a separate exclusively created bounded file. Parent validates exact output schema/types/digests, fixed strings and result projection against locally derived frozen expected values before publishing. That second validation includes an explicit duplicate-key rejection rule.

A missing first checkpoint makes the first unavailable; a present second checkpoint without a validated first is rejected for order. If checkpoint one is invalid, checkpoint two is never published even if locally valid. A valid prefix may be retained after child failure/timeout or a lost phase event: state validated means only that its JSON matches the finite frozen validator/bindings, not that the run or real inference succeeded. No checkpoint means unavailable, never not_in_library or false. A failed validator gives rejected with null projection; no fallback reconstruction from the expected answer. If reconciliation itself fails or times out, all cases are not_reconciled with null projections (do not trust uncommitted partial verifier output).

## Public projection and success rule

Raw results can contain reason, candidates, model_assessment or extra fields ignored by v2. Therefore even a v2-valid raw result is never copied wholesale into the public report. After exact validation and binding, construct only the projection keys in design.json: the exact frozen status/answer/verdict, approved inspection/package digest/import, false consent/refresh and projection_source=frozen_protocol_after_validated_match. The answer is equal to the validated result but emitted from trusted frozen data. Unknown has null answer/verdict/inspection/package digest. This preserves the full answer for these two finite cases, not all arbitrary model text. A rejected/unavailable/not_reconciled case must have null projection. No reason/candidate/prompt/log/exception/path/run identifier/free text or arbitrary child labels are published. For valid bounded checkpoints a full raw-file SHA256 may be recorded; rejected oversized files use explicitly observed-prefix hash/byte count, or null digest. Never label a prefix a full file digest.

The public report has only the keys in design.json, fixed vocabularies and bounded typed supervisor metadata (allowlist status/phase names, counts, observed hashes, cleanup booleans; no caller argv or raw output). Overall passed requires every condition in design.json. Any worker timeout/nonzero/invalid event/cleanup issue, missing or invalid checkpoint, reconciliation failure or report/owned-directory cleanup error makes the run non-passing even when both results validate. A retained validated capital answer alongside a failed unknown case must visibly remain an overall failed report. Individual semantic status is distinct from case validation state and overall execution outcome. No result is a new factual review, curation, routing decision or API publication.

## One outer budget and cleanup

The existing Q8 ceilings remain maxima: total600s/startup180s/each case180s. Start the outer monotonic clock before local setup. Reserve at most570s for worker supervision including its own2s cleanup,20s for reconciliation including its own cleanup, and10s for bounded report construction/owned-directory teardown. Supervisor invocation uses min(570, remaining minus30), case phase caps at180. Reconciliation uses min(20, remaining minus10); if insufficient, skip it and report not_reconciled, never grant a fresh20s/600s window. The concrete schedule and minimum launch allocation below replace the former unspecified phase-cap obligation. Parent reports failures with fixed codes and preserves no raw errors. Case checks must be pure bounded local work with no network.

New child startup or serialization may still overrun under OS stalls; retain explicit budget observations rather than a hard-real-time guarantee. Report encoding is bounded at65536 bytes, written once to a caller-specified fresh output outside the temporary directory; existing output is an error, no overwrite. Validate/encode in memory, delete only the owned ephemeral directory, then publish the report. Cleanup failure prohibits passed. If final report write fails, return fixed error/nonzero without claiming that a report exists. No retry/poll/model loop. Future implementation must specify orphan cleanup after parent crashes; this design promises best-effort normal-exit cleanup only, not crash cleanup or Docker ownership removal.
