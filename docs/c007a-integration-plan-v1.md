## Concrete implementation sequence

1. Add a separately versioned detached-review attachment adapter. Consume exact
   original record/review bytes and an explicit hash-bound attachment manifest.
   Preserve the original review kind, complete input binding, raw/canonical hash
   domains, source checks, predicate findings, author/reviewer/decision actor/
   recorder and owner dependence. Do not turn a design/code review into a factual
   source review or manufacture missing legacy fields. Coordinate validator
   changes with Factfinder through a new exact Market contract; do not edit
   Factfinder's artifacts or validator as part of a consumer-only change.
2. Integrate the attachment into an **offline pending-view fixture** first.
   `library_view.derive_view` must display accepted source review separately from
   pending curation, and move only the exactly bound creation-time no-review note
   to history. Keep all substantive limitations, review coverage and source
   dependence. Reject changed claim/version/artifact/raw bytes/digest/anchor,
   duplicate/conflicting attachment, and unknown/unresolved/withdrawn correction
   disposition. The three posts' supplied state is not an authenticated or fresh
   resolver; it cannot itself authorize publication. Do not weaken the separate
   W020 provenance requirements or inherit runtime authority from the preview.
3. Define a new explicit catalog schema for predicate answer projections and
   literal matching. Q01 must answer ranking/P1/S1 only; Q02 must retain the dated
   2020-12-08 joint snow-surface announcement/P2/S3a; Q03 must attribute reported
   orthometric/IHRS method to S2. Freeze/review the exact projected answer texts
   and source selections, binding each to the unchanged full record digest and
   detached factual review. A routing review covers the projection/selection,
   never a new measurement verdict. Q04/Q05 clarify metric/date/surface; Q06–Q15
   remain unmapped. Do not silently send these queries through legacy whole-
   answer routing or normalization. Preserve legacy mappings under their current
   policy. New schema/features must fail closed in older readers/exporters;
   unknown fields cannot be ignored and downgraded to a whole-claim route.
4. Carry the same explicit semantics through `ask.py`, `export_api_seed.py`,
   `export_public_snapshot.py`, and the Convex alias/import/check interfaces.
   Read-only inspection shows Convex aliases support only claim/clarify and
   `checks.ts` returns the package answer. Changes there require the current
   Convex skill and fresh exact implementation/integration review; they were not
   exercised or edited in this evaluation. The semantic API also needs its own
   scoped growth/runtime evaluation; Python results do not establish that path.
5. Only after the offline pending integration passes review should an explicit
   non-author curation decision select the exact candidate, attachment and
   routing projection. Record actual decision actor and recorder separately,
   their eligibility and shared-owner/provider/implementation exposure. A
   reviewer differs from the candidate author; that does not automatically make
   every later decision independent. Preserve prior target-specific abstention
   and limited supplement. Obtain separate growth/snapshot evidence and existing
   owner publication consent before active inputs/export/import/runtime change.
