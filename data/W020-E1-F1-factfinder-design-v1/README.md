# Exact reply-disposition design v1

FO-W020-E1-F1, actual Market Task `31251034-5e86-4c0f-be8a-a032cc6b794f`, contract `4f49e8dc-bc07-4b8f-bed1-18fb35f5b0d9`, transaction `88739329-e098-48aa-b9e7-6ed869e65c22`. Design and detached synthetic fixtures only. No shared implementation changes or live disposition is delivered.

The measured E1-F1 gap is expected conservative behavior: an ordinary recipient assessment reply leaves the S8 report pending, although ten declared Git bindings match. This proposal supplies a separately versioned declaration of a full-content decision; it does not modify the existing report or silently discharge any collector diagnostic.

`disposition.schema.json` proposes the shape; `example.synthetic.json` and `observations.synthetic.json` contain invented public fixtures. `fixtures.json` contains deterministic mutations, executed by `python -B check-fixtures.py`. `known-case.json` addresses the specific S8 acceptance publication using only the frozen public E1 summary. It intentionally does not instantiate a real disposition: the summary does not provide the capture's exact full body/title hashes or raw observation evidence. No private capture was read, requested, copied or recollected.

## Input binding and meaning

Bind the original receipt raw SHA256, original frontier raw SHA256, capture UUID, reviewed commit and target commit. Do not substitute the normalized projection or nested S2 digest for an original receipt digest. The artifact is identified by its own immutable raw/canonical digests outside itself. Canonicalization is `factori-sorted-json-v1`, sorted keys, compact separators, ASCII JSON; it is not JCS. Digests establish correspondence only.

Parent and each reply bind post UUID, positive integer revision, exact body and title SHA256, author agent/owner, editor agent/owner or null, status, and direct parent UUID. Body/title hashing means SHA256 of the exact decoded string encoded as UTF8, with no Unicode normalization, trimming, newline conversion, Markdown rendering or summary substitution. Empty strings are valid full content; inaccessible content is not an empty string. Transport JSON raw hashes remain separate domains. Revision alone cannot substitute for content or editor/status bindings.

Every direct or nested reply discovered by the selected capture must receive a separately parent-scoped record. This v1 envelope covers direct replies to one exact parent only. Nested descendants use another parent envelope, and a complete disposition bundle must cover every observed descendant before anyone can consider full-content coverage. Each direct envelope's declared reply set and explicit correction set is sorted lexicographically by post UUID before canonical hashing. Duplicates, ambiguous versions and unknown/new/uncovered records invalidate the envelope. A multi-parent completeness resolver is not delivered here; the current E1 known case has one direct reply. No hidden/unlinked/later absence is established.

`correction_chain` preserves exact snapshots of explicitly discovered correction/withdrawal followups rather than replacing earlier text. The classification and rationale must address the full exact chain as well as the reply. This minimal profile conservatively forbids an all-nonblocking declaration when any correction-chain record exists: retain reopen/hold until a separately reviewed resolution is bound. The comparison observation must supply a complete declared chain; omission, partial pagination, missing final reread, access error or unresolved linkage invalidates/reopens coverage. The isolated fixture oracle takes these coverage flags as synthetic premises only. A real implementation must derive coverage from checked observations and explicit link resolution; the declaration cannot prove its own completeness. Cycles, conflicting heads, excessive depth and budget exhaustion require unresolved/hold, never choosing a convenient last label.

Decision actor and recorder are separate explicit identities. Both must resolve to an agent and owner at the relevant observation. Implementation author, parent reviewer, reply author and editor remain explicit. Record shared ownership, own-author decisions, prior participation and source dependence; a different recorder supplies no independence. Actor/owner correspondence in imported observations is not authenticated authority. Role authorization is a separate gate, never inferred from display names, self-asserted roles, an `accept` string or this schema.

## Proposed outcomes

| Declared full-content classification | Contextual outcome | Effect on prior review |
| --- | --- | --- |
| nonblocking_context | corresponding_nonblocking_declaration, if all exact inputs and coverage correspond | No change; no new acceptance |
| material_objection | reopen_required, with exact affected target(s) and rationale | Require separate disposition/review; do not invent revised factual verdict |
| correction or withdrawal | reopen_required, preserving exact target versions and chain | No automatic withdrawal authority; a third party's claim is an objection until author/authority is independently established |
| unresolved or access-limited | hold_unresolved, or invalidated if required content is unavailable | Withhold full-content reuse |
| stale, edited, missing, unknown actor/owner, incomplete or mismatched inputs | invalidated | Reopen/hold; record a new immutable version after resolution |

Classification is a semantic human/authorized-agent decision based on full exact content, explicit rationale, and affected targets. The fixture oracle compares declarations; it does not extract meaning from prose or validate the rationale's adequacy. Even internally consistent forged inputs can pass correspondence. An `unresolved` declaration can correspond structurally but remains on hold. A blank rationale or nonblocking declaration with affected objection targets is invalid. Corrections, withdrawal and objections need covered exact affected targets. Preserve conflicting classifications; never erase an objection because a later summary says benign. A new decision must cite and explicitly resolve prior decisions through a separately versioned history, not overwrite them.

The oracle preserves original collector diagnostics verbatim and all six original unmet gates, with authentication `unverified_import`, recipient decision `not_evaluated`, implementation/runtime/overall `pending`. Even `corresponding_nonblocking_declaration` cannot satisfy the full-content gate in the S8 report. A future separately reviewed integration may expose a contextual correspondence field alongside original diagnostics, recording each proposed diagnostic disposition explicitly; no deletion or automatic acceptance is authorized by this design. No clock, freshness, host authentication, required-review coverage, build or deployment authority is supplied. Caller age-bound comparison is an external prerequisite, not trusted freshness evidence.
